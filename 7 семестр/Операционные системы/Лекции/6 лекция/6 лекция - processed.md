## 1. 🔀 Перенаправление ввода-вывода (продолжение)

### Here-Document

- `[n]<< word` — перенаправляет последовательность строк в дескриптор `n` (по умолчанию 0 — stdin).
  - `word` — ключевое слово, обозначающее конец последовательности.
- `[n]<<- word` — аналогично, но удаляет табуляции в начале строк.

**Пример:**
```bash
cat << end-marker
qwerty
asdf
end-marker
```

**Вывод:**
```
qwerty
asdf
```

### Дублирование дескрипторов

| Синтаксис | Описание |
| :--- | :--- |
| `[n]& word` | Если `word` — число существующего дескриптора, то `n` теперь ссылается на тот же файл; если `word` — `-`, дескриптор `n` закрывается. По умолчанию `n` = 0 |
| `[n]>& word` | Аналогично, но по умолчанию `n` = 1 (stdout) |

**Пример:**
```bash
ls 1> /dev/null 2>&1
```
Весь вывод `ls` (и stdout, и stderr) отбрасывается.

> [!tip] Пояснение
> `2>&1` — «направить дескриптор 2 (stderr) туда же, куда указывает дескриптор 1 (stdout)». Порядок важен: сначала перенаправляем stdout в `/dev/null`, потом stderr — в stdout.

## 2. 🔗 Конвейер (Pipeline)

> [!abstract] Определение
> **Конвейер** — механизм, при котором стандартный вывод одной программы передаётся в стандартный ввод другой.

**Синтаксис:**
```
prog1 | prog2 [| prog3 …]
```

**Механизм:** Специальный тип файла — **FIFO** (named pipe), ассоциируемый с двумя файловыми дескрипторами.

**Пример:**
```bash
ls -1 | sort | more
```
Перечислить имена файлов текущего каталога (по одному в строке), отсортировать по алфавиту и постранично вывести на экран.

> [!note] Ссылка
> POSIX, раздел 2.9.2: https://pubs.opengroup.org/onlinepubs/9699919799/utilities/V3_chap02.html#tag_18_07

## 3. 🖼️ Концепция графического интерфейса

- Используется вся площадь экрана и модель **поэлементно адресуемого растрового изображения (bitmap)**.
- Изображение = двумерный массив точек (**pixel**), цвет и яркость каждой определяются независимо.
- Вводится **система экранных координат**:
  - Обычно декартова прямоугольная.
  - Начало координат — **левый верхний угол** экрана.
  - Ось OX — вправо, OY — вниз.
- За каждой командой закрепляется **область экрана**, в которой отображена информация о команде.
- Для выполнения команды нужно **выбрать область** (мышь, сенсорный экран) и **запустить** её (нажатие кнопки, касание).

### Пример: Norton Commander

- Классический файловый менеджер для DOS (1986).
- Двухпанельный интерфейс, горячие клавиши.

### Пример: Midnight Commander (mc)

- Современный аналог для UNIX-подобных систем.
- Установка: `sudo apt install mc`.
- Официальный сайт: https://midnight-commander.org/

## 4. 🖱️ WIMP HIDs: устройства координатного ввода

### Световое перо

- Изобретено в **MIT** в середине 1950-х.
- Работа со световым пером на IBM 2250 (1969).

### Компьютерная мышь

- Изобретатель: **Дуглас Энгельбарт** (Douglas Carl Engelbart), 30.01.1925 – 02.07.2013.
- Патент: «X-Y Position Indicator for a Display System», U.S. Patent 3,541,541 от 17 ноября 1970.

### Графический планшет

- Идея запатентована **задолго до появления ЭВМ**: Elisha Gray, Telautograph, U.S. Patent 386,815 (1888).
- **RAND Tablet** — первый широко распространённый графический планшет, представлен RAND Corporation в 1964.

### Сенсорный экран

- Впервые описан **Эриком Джонсоном** (Royal Radar Establishment) в 1965.
- Прозрачный сенсорный экран впервые изготовлен в **CERN** в начале 1970-х.
- Слева — фрагмент сенсорного экрана пульта управления ускорителем CERN (1977).
- Справа — первый прототип сенсорного экрана CERN (1972).

## 5. ⚠️ Трудности реализации многооконного интерфейса WIMP

> [!warning] Проблема
> При наличии **перекрывающихся окон** одна и та же экранная точка (x, y) может быть отнесена к нескольким окнам одновременно.
> - Конфликты при выводе изображений в окна.
> - Неопределённость при использовании устройств координатного ввода.

### Решение: Z-порядок

- Вводится **виртуальный z-порядок окон**.
- С каждым окном сопоставляется числовой индекс — виртуальная координата z (ось OZ направлена от экрана к пользователю).
- **Для вывода:** окна отрисовываются в порядке возрастания z.
- **Для ввода:** приоритет отдаётся окну с **наибольшим z**.

## 6. 📨 Интерфейс WIMP, управляемый сообщениями

**Схема:**
- **Устройства вывода** ↔ **Менеджер окон** (обработка вывода).
- **Устройства ввода** → **Менеджер окон** (обработка ввода и формирование сообщений).
- **Очереди сообщений** → **Приложение** (селектор → действия).
- **Очередь запросов** ← **Приложение**.

> [!success] Преимущества
> - Из программ исключается громоздкий системно-зависимый код низкоуровневого взаимодействия с HIDs.
> - Все программы имеют **единообразный интерфейс** с общей концепцией управления.
> - Облегчает обучение пользователей.
> - Делает работу с новыми программами интуитивно понятной.

## 7. 🪟 X Window System

> [!info] История
> - Традиционная оконная система для UNIX и UNIX-подобных ОС.
> - Разработана **MIT в 1984 году** на основе оконной системы **W** (Стэнфордский университет, начало 1980-х, для ОС V-System).
> - Название **X** — потому что в алфавите X идёт за W.
> - С 2004 года курируется **X.Org Foundation** (https://x.org/wiki/).
> - Текущая версия: **X11R7.7** от 6 июня 2012.
> - **Не имеет встроенного менеджера окон** (используется внешний) — легко менять внешний вид при сохранении общей концепции.

### Архитектура X-Server / Xlib / X-protocol

- **X-Server** работает на клиентском компьютере (X-терминале), отображает окна, принимает ввод от HIDs и отправляет сообщения программе через **X-Protocol**.
- Прикладная программа может работать на **отдельном компьютере** и взаимодействовать с X-Server через X-Protocol.
- **Xlib** — библиотека для удобства разработки приложений, скрывает детали X-Protocol.

### Библиотека Xlib

Предоставляет API с удобными функциями:

| Функция | Назначение |
| :--- | :--- |
| `XOpenDisplay` | Устанавливает соединение с менеджером окон |
| `XCreateWindow` | Создаёт новое окно |
| `XDrawLine` | Рисует отрезок по координатам концов |
| `XDrawLines` | Рисует ломаную по координатам вершин |
| `XDrawArc` | Рисует дугу эллипса, вписанного в прямоугольник |
| `XDrawString` | Выводит текстовую строку в указанную область окна |

### Сообщения X Window System

```c
XEvent report; // union: все возможные типы сообщений
while (1) { // цикл получения сообщений
    XNextEvent(display, &report); // ожидание сообщения
    switch (report.type) { // классификация и обработка
        // struct XMotionEvent — перемещение мыши
        // struct XButtonEvent — кнопки мыши
        // struct XKeyEvent — клавиатура
        // struct XExposeEvent — запрос перерисовки окна
    }
}
```

### Проблемы и недостатки X Window System

- Оригинальная X брала на себя управление **всеми HIDs**, включая распределение видеопамяти и установку режимов.
- После 2004 года из неё удалено **более 300 тыс. строк кода** (функциональность перенесена в драйверы ОС), но реализация всё ещё далека от оптимальной.
- Проблемы **синхронизации** (неопределённость выполнения) с ростом производительности.
- Громоздкая **Xlib** (более 150 тыс. строк) содержит много устаревшего кода.

## 8. 🌊 Оконная система Wayland

> [!info] История
> - **Wayland** — новая оконная система для Linux, исправляющая проблемы X.
> - Автор: **Кристиан Хогсберг** (Kristian Høgsberg), 2008 год.
> - Название — от города **Вэйланд** (США).
> - Первая версия — 2008 (текущая 1.26.0 от 16.07.2026).
> - Официальный сайт: https://wayland.freedesktop.org/
> - Первый дистрибутив с Wayland по умолчанию — **Fedora Linux v.25** (2017).
> - Сейчас используется по умолчанию в Ubuntu, Fedora, SUSE, Debian.
> - Переход затянулся из-за проблем совместимости со старым ПО.
> - Для запуска X-приложений в среде Wayland — **Xwayland** (https://wayland.freedesktop.org/xserver.html).

### Протокол Wayland

- Протоколы описывают взаимодействие между **клиентом** и **сервером**.
- Описываются файлами **XML**, на основе которых автоматически генерируется исходный код.
- **Утилита `wayland-scanner`** генерирует заголовочный файл и исходный код:

```bash
wayland-scanner client-header \
  $(pkg-config wayland-protocols --variable=pkgdatadir)/stable/xdg-shell/xdg-shell.xml \
  xdg-shell-client-protocol.h

wayland-scanner private-code \
  $(pkg-config wayland-protocols --variable=pkgdatadir)/stable/xdg-shell/xdg-shell.xml \
  xdg-shell-client-protocol.c
```

### Интерфейсы Wayland

> [!abstract] Определение
> **Интерфейс Wayland** — программный модуль, который:
> 1. Предоставляет функции для отправки клиентских запросов серверу (**requests**).
> 2. Поддерживает получение и обработку сообщений сервера о событиях (**events**).

- Для обработки сообщений сервера клиент регистрирует **функции обратного вызова (callbacks)**.
- Набор параметров функций определяется **протоколом Wayland** (XML).

**Регистрация callbacks:**
```c
int interface_name_add_listener(
    interface_name* instance,          // экземпляр интерфейса
    const interface_name_listener* listener, // структура с указателями на функции
    void* data                         // произвольный указатель, передаётся в callbacks
);
```
Возвращает 0 при успехе, –1 при ошибке.

### Пример интерфейса: wl_pointer

Интерфейс для поддержки устройств координатного ввода (мышь, сенсорная панель).

**Requests (запросы):**
- `wl_pointer::set_cursor` — установка изображения указателя.
- `wl_pointer::release` — освобождение устройства.

**Events (события):**
- `wl_pointer::enter` — указатель вошёл на поверхность (`wl_surface`).
- `wl_pointer::leave` — указатель вышел за границу поверхности.
- `wl_pointer::motion` — указатель переместился (координаты + время до мс).
- `wl_pointer::button` — нажатие/отпускание кнопки.
- `wl_pointer::axis` — поворот, нажатие, отклонение колеса прокрутки.
- `wl_pointer::axis_relative_direction` — направление прокрутки (движение пальца на сенсорной панели).

### Типичная последовательность действий клиента Wayland

1. **Подключение к серверу:**
   ```c
   wl_display = wl_display_connect(NULL)
   ```
2. **Получение реестра глобальных объектов:**
   ```c
   wl_registry = wl_display_get_registry(wl_display)
   ```
3. **Получение требуемых глобальных объектов из реестра:**
   ```c
   wl_display_roundtrip(wl_display)
   ```
   - `wl_compositor` — интерфейс компоновщика.
   - `xdg_wm_base` — интерфейс базовых операций оконного менеджера.
4. **Создание поверхности окна:**
   ```c
   wl_surface = wl_compositor_create_surface(wl_compositor)
   ```
   Поверхность — прямоугольная область, которая может отображаться на экране и принимать ввод.
5. **Назначение поверхности роли обычного (toplevel) окна:**
   ```c
   xdg_surface = xdg_wm_base_get_xdg_surface(xdg_wm_base, wl_surface)
   xdg_toplevel = xdg_surface_get_toplevel(xdg_surface)
   ```
6. **Создание буфера окна в разделяемой памяти и связывание с поверхностью.**
7. **Ожидание сообщения от сервера:**
   ```c
   wl_display_dispatch(display)
   ```
