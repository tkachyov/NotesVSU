# 🔬 Лекция 5: Микроядра, экзоядро, наноядро и командный интерфейс

> [!info] Основная информация
> **Тема:** Микроядро (Mach, L4, seL4), экзоядро, наноядро/гипервизор. Пользовательский интерфейс. Командная строка UNIX.

---
## 1. 🧩 Микроядро (µ-ядро) — продолжение

> [!abstract] Основная идея
> Вывести подключаемые модули в **пользовательский режим** для повышения надёжности и снижения уязвимости.

**Ключевые свойства:**
- Изолированные сервисные модули не представляют угрозы.
- Сбой одного модуля не нарушает работу ядра и других модулей.
- При сбое сервисный модуль может быть аварийно завершён и перезапущен.
- Злоумышленник не может получить доступ к ядру или аппаратным средствам.

### Показатели качества

| Показатель | Оценка |
| :--- | :---: |
| Надёжность | ✅ Высокая |
| Уязвимость | ✅ Низкая |
| Производительность | ❌ Низкая |
| Расширяемость | ✅ Хорошая |
| Переносимость | ✅ Хорошая |

> [!warning] Причина низкой производительности
> Частые переключения между пользовательским и режимом ядра + накладные расходы на обмен сообщениями между сервисами.

## 2. 🍏 Ядро Mach

> [!info] Историческая справка
> **Mach** — первое распространённое микроядро, оказавшее влияние на всю микроядерную архитектуру.

- **Первоначальное название:** MUCK (Multi-User Communication Kernel).
- **Разработка:** Университет Карнеги-Меллона, 1985, для DEC VAX.
- **Цель:** Замена традиционному ядру BSD UNIX.
- **Развитие:** До 1994 (Mach 3.0).

### Основные концепции

- **Порты** — основной механизм IPC.
  - Порт = разновидность очереди сообщений на разделяемой памяти.
  - Сервисы через системный вызов получали доступ к порту и использовали его для быстрого взаимодействия с ядром.
- **Модель выполнения:**
  - **Задача (task)** — набор ресурсов для выполнения потоков.
  - **Поток (thread)** — единица планирования (аналог LWP).
  - В одной задаче может быть много потоков, разделяющих ресурсы.

### Архитектурные решения Mach в современных системах

| Система | Использование |
| :--- | :--- |
| **GNU Hurd** | Официальное ядро GNU на базе GNU Mach (исходный код Mach 3.0 rel. MK84, 1996) |
| **macOS / iOS** | Гибридное ядро **XNU**: микроядро Mach + ядро BSD (4.4BSD-Lite2 / FreeBSD) для POSIX |
| **NeXTSTEP** | С 1988 — Mach 2.x, с 1996 — Mach 3.0 + решения из OSF/1 и MkLinux |

## 3. 🧬 Семейство ядер L4

> [!info] История
> **L4** создано Йохеном Лидтке (Jochen Liedtke) для i386, представлено в **1993 году**.
> - Существенно повышена производительность за счёт оптимизации IPC и эффективного использования кэша.
> - Перенесено на многие платформы, продолжает развиваться.

### Концепции L4

**Основной принцип проектирования:**
> Функция реализуется в микроядре только если её перенос в пользовательское пространство сделает работу ОС невозможной.

**Базовые абстракции ядра L4:**

| Абстракция | Описание |
| :--- | :--- |
| **VSpace (Virtual Address Space)** | Ядро поддерживает аппаратную трансляцию адресов, преобразует Page Fault в синхронные сообщения |
| **CSpace (Capability Space)** | Таблица токенов, разрешающих доступ к объектам ядра |
| **TCB (Thread Control Block)** | Приоритет потока, ссылки на VSpace и CSpace, регистровый контекст, буфер для сообщений |
| **Примитивы IPC** | Точки подключения (Endpoints) для синхронных сообщений, асинхронные уведомления (Notification Objects), разделяемая память (Shared Memory) |

### seL4 — верифицированное микроядро

- Разрабатывается компанией **NICTA** (National ICT Australia) с **2006 года**.
- **2009:** Впервые для ОС общего назначения получено **формальное доказательство корректности кода**.
  - На основе **логики Хоара**.
- **29 июля 2014:** Исходный код и доказательства опубликованы под **GPL v2**.

> [!success] Что именно доказано для seL4
> - Невозможно переполнение буфера (Buffer overflows)
> - Невозможно разыменование нулевого указателя (Null pointer dereferencing)
> - Невозможно использование памяти после освобождения (Use-after-free)
> - Отсутствие утечек памяти (Memory leaks)
> - Невозможно обойти правила разграничения доступа (Privilege escalation)

### Примеры современного применения L4

| Область | Пример |
| :--- | :--- |
| **Apple Secure Enclave** | Изолированный сопроцессор безопасности, работает под управлением **serOS** на базе L4 |
| **Qualcomm Snapdragon** | Встроенное ПО в чипах работает под управлением ОС на базе L4 |
| **Транспорт** | Модули Magna, Bosch для изоляции вспомогательных систем (климат, мультимедиа) от критичных (двигатель, ABS/ESP) |

### Микроядро: итог

- **Расцвет:** конец 1980-х — первая половина 1990-х.
- **Причина непопулярности:** низкая производительность.
- **Сейчас:** применяется там, где **надёжность важнее производительности** (встраиваемые системы).

## 4. 🌐 Экзоядро (внешнее ядро)

> [!abstract] Основная идея
> Исключить медленные механизмы IPC за счёт загрузки всех сервисов в **виртуальное адресное пространство процесса**.

- Сервисы собираются в **библиотеку** (библиотечную ОС), размещаемую в адресном пространстве пользовательской программы.
- Разные процессы могут использовать разные библиотечные ОС.
- **Цель:** повышение производительности.
- Вместо медленного обмена сообщениями — обычные вызовы функций, не требующие обращения к ядру.

> [!info] История
> Концепцию предложили в **1995 году** Доусон Энглер, Франс Каашуэк и Джеймс О'Тул (MIT Lab for Computer Science).
> В MIT создано экзоядро **XOK** (произносится [za:k]) и библиотечная ОС **ExOS** (эмулирует FreeBSD).
> - [Ссылка на архив](https://pdos.csail.mit.edu/exo/exopc-06-22-2000.tar.gz)
> - [Руководство](https://pdos.csail.mit.edu/archive/exo/exo-guide/guide.html)

> [!note] Итог
> Экзоядро потенциально способно обеспечить высокие показатели качества, но **не получило широкого распространения** в массовых ОС.

## 5. 🍎 Гибридная архитектура macOS

- **Приложение** → **API** → **Библиотека libSystem.dylib** → **ABI** → **ВАП ядра**.
- **Драйвер dext** → **DriverKit API** → **Библиотека libDriverKit.dylib** → **DriverKit ABI** → **ВАП ядра**.
- Внутри ядра:
  - **Диспетчер системных вызовов**
  - **BSD** (файловая система, сеть, вторичная обработка прерываний, POSIX)
  - **I/O Kit**
  - **Mach** (первичная обработка прерываний, управление потоками, планирование задач, виртуальная память, взаимодействие потоков и синхронизация)

> [!note] Особенность
> Документированный и нестабильный ABI, программы должны использовать библиотеку libSystem.dylib.

## 6. 🪟 Гибридная архитектура Windows NT

- **Приложение Windows** → **Win32 API** → **kernel32.dll, advapi32.dll, user32.dll, gdi32.dll** → **Недокументированный API** → **ntdll.dll**.
- **Сервисы Microsoft** (танцоры) → **Win32 API** → **kernel32.dll, advapi32.dll** → **Недокументированный API** → **ntdll.dll**.
- **Приложение POSIX** → **POSIX API** (сторонние библиотеки: Cygwin, MSYS2, MinGW) → **Win32 API** → **kernel32.dll** → **Недокументированный API** → **ntdll.dll**.
- Всё это в **ВАП процесса**, а в **ВАП ядра** — **Компоненты режима ядра** (ABI).

> [!warning] Важно
> Сервисы Microsoft могут использовать прямые обращения к недокументированному API ntdll.dll.

## 7. ⚡ Наноядро (гипервизор)

> [!abstract] Определение
> **Наноядро** располагается между аппаратной платформой и ядром гостевой ОС.
> - Перехватывает прерывания от аппаратной платформы и диспетчеризирует их между гостевыми ОС.
> - Сохраняет аппаратный контекст и переключает гостевые ОС подобно тому, как обычная многозадачная ОС переключает процессы.

- **Термин впервые:** 1992 год, по отношению к ядру ОС **KeyKOS**.
- **KeyKOS** — разработка Tumshare, Inc. для IBM System/370 (с начала 1970-х), позволяла эмулировать VM, MVS, UNIX.
- **Современное название:** **гипервизор (hypervisor)**.

## 8. 🖥️ Пользовательский интерфейс ОС

- **HCI (Human Computer Interface)** — частный случай **HMI (Human Machine Interface)**.
- Учитывает эргономику, техническую эстетику, физиологию и психологию.
- Опирается на **HID (Human Interface Device)**.
- Основы заложены в начале 1960-х: Джозеф Ликлайдер, Айвен Сазерленд, Дуглас Энгельбарт.

### Классификация интерфейсов

| Пакетный интерфейс | Интерактивный интерфейс |
| :--- | :--- |
| Пакет заданий выполняется до конца (или ошибки) без взаимодействия с человеком | **CLI** — диалог с использованием формализованных текстовых сообщений<br>**WIMP** — диалог с использованием интуитивно понятных графических образов<br>**SILK** — естественный диалог с использованием речи и жестов |

## 9. 💻 Командная строка UNIX-подобных систем

- **Командная оболочка (command shell)** — программа, автоматически запускается при входе.
- **bash** — наиболее распространена (GNU).
- Режимы:
  - **Интерактивный** — последовательный ввод команд.
  - **Сценарий (shell script)** — выполнение последовательности команд из файла.

### Запуск программы

`program_name [parameter_1 [parameter_2 …]]`

- `program_name` может содержать путь:
  - **Абсолютный** — от корня (`/home/user1/my-program`).
  - **Относительный** — от текущего каталога (`./my-program`).
- Если не начинается с `/` или `./`, оболочка ищет файл в каталогах из переменной **PATH**.

```bash
echo $PATH
# /home/andrei/.local/bin:/usr/local/sbin:/usr/local/bin:...
```

> [!tip] Пробелы в аргументах
> Если `program_name` или параметр содержит пробелы, используйте одинарные или двойные кавычки.

### Утилиты командной строки

- Большинство команд — сервисные программы-утилиты.
- **POSIX** определяет перечень обязательных утилит.
- В большинстве UNIX-подобных систем используется реализация GNU.
- Примеры: `cat`, `ps`, `ls`, `rm`.

### Аргументы утилит (опции)

Стандарт POSIX определяет нотацию:
`-c[[ ]параметр]`, где `c` — ключ опции.

- **Флаги** — опции без параметров (включают/отключают режимы).
- Опции можно указывать в любом порядке, объединять флаги: `-abc` = `-a -b -c`.
- Если аргумент опции **опциональный**, он указывается после ключа **без пробела**: `-e33` верно, `-e 33` неверно.
- Обязательный параметр можно писать с пробелом или без.
- Опция `--` завершает список опций: всё после неё — обычные аргументы.

### Длинные опции GNU

- Начинаются с `--`, название не ограничено одним символом.
- Пример: `--interface=wlan0` вместо `-iwlan0`.
- Цель — удобство и интуитивная понятность.
- Поддерживается функцией `getopt_long` (`#include <getopt.h>`).

## 10. 🔀 Перенаправление ввода-вывода

**Общий синтаксис:** `[n]redir-op word`

- `n` — десятичный номер файлового дескриптора (по умолчанию 0 для ввода, 1 для вывода).
- `redir-op` — оператор: `>`, `>|`, `>>`, `<<`, `<<-`, `<`.

### Перенаправление ввода

- `[n]< word` — открывает файл `word` и связывает с дескриптором `n`.
- Пример: `cat < file` — `cat` читает из файла вместо клавиатуры.

### Перенаправление вывода

- `[n]> word` — перенаправляет вывод в файл `word`.
  - Не работает при включённой защите (`set -C`).
- `[n]>| word` — игнорирует защиту от перезаписи.
- `[n]>> word` — дописывает в конец файла.
- Пример: `ls 2> /dev/null` — ошибки отбрасываются.

### Here-Document

- `[n]<< word` — перенаправляет последовательность строк в дескриптор `n`.
  - `word` — ключевое слово, обозначающее конец последовательности.
- `[n]<<- word` — аналогично, но удаляет табуляции в начале строк.

```bash
cat << end-marker
qwerty
asdf
end-marker
```

**Вывод:**
```
qwerty
asdf
```
