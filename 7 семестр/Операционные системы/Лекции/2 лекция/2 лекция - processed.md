## 1. 🪟 Появление Windows

### Windows 1.01 (20 ноября 1985)

- **Начало работ:** Сентябрь 1981, проект «Interface Manager» — графическая оболочка для MS-DOS.
- **Контекст:** Толчком послужили Visi On (1983), IBM TopView и DESQview (1985).
- **Особенности:**
  - ❌ Не самодостаточная система: надстройка над MS-DOS версии ≥ 2.0.
  - 🪟 Только **неперекрывающиеся окна**, переключение между программами без перезапуска.
  - 👨‍💻 24 программиста, 85% кода на C.
- **Итог:** Уступала альтернативам, не получила большого распространения.

### Windows 2.0 (9 декабря 1987)

- **Нововведения:**
  - 🪟 Перекрывающиеся окна.
  - 🎨 16 цветов в режиме VGA.
  - 💾 Поддержка расширенной памяти (EMS) на процессоре Intel 80286.
- **Особенность:** Последняя версия Windows, работавшая **без жёсткого диска**.
- **Рост популярности:** Одновременно вышли Microsoft Excel и Word, что подстегнуло спрос.

### Windows NT (27 июля 1993)

> [!success] Ключевая веха
> **NT = New Technology.** Вся современная линейка Windows — развитие Windows NT.

- **Ключевые технологии:**
  - 🧠 Виртуальная память.
  - ⚡ Вытесняющая многозадачность.
  - 🔒 Разграничение доступа.
  - 📂 Принципиально новая файловая система **NTFS**.
- **Руководитель:** Дэйв Катлер (Dave Cutler), перешёл в Microsoft в 1988 из DEC (работал над RSX-11, VMS, VAXELN, MICA).

## 2. 🍏 Предыстория macOS

### Apple (1976–1977)

- **Основана:** 1 апреля 1976 Стивом Джобсом, Стивом Возняком и Рональдом Уэйном.
- **Apple I:** Первый продукт (июль 1976, $666.66 — только плата, корпус и клавиатуру покупатель подбирал сам).
- **Apple Computer зарегистрирована:** 3 января 1977.
- **Apple II:** Представлен 16 апреля 1977 (продано > 5 млн).

### Apple Macintosh (24 января 1984)

- **Процессор:** 32-битный Motorola 68000.
- **ОС:** Проприетарная система с графическим интерфейсом, разработанная под влиянием идей **Xerox**.

### Появление macOS (2001)

- **С 2001 года:** Apple комплектует компьютеры macOS (изначально Mac OS X, с 2012 — OS X, с 2016 — macOS).
- **Основа:** **NeXTSTEP** — ОС компании NeXT, основанной Джобсом после ухода из Apple в 1985.
- **Корни:** NeXTSTEP базируется на **UNIX BSD 4.4** → macOS относится к «историческим» UNIX-системам.
- **Возвращение Джобса:** В конце 1996 Apple поглотила NeXT, 20 декабря 1996 Джобс официально вернулся.

## 3. 🐧 Предыстория Linux

### MINIX (1987)

- **Автор:** Эндрю Таненбаум (Амстердамский свободный университет).
- **Название:** MINIX = MINI unIX.
- **Совместимость:** По системным вызовам совместим с **UNIX V7** (AT&T, 1979).
- **Код:** 12 000 строк на C, напечатан в учебнике Таненбаума «Операционные системы: разработка и реализация».
- **Важно:** Таненбаум настаивал на учебном характере и **не принимал патчи** от читателей.

### Появление Linux (1991)

- **Автор:** Линус Торвальдс, студент Хельсинкского университета.
- **Январь 1991:** Установил MINIX на IBM PC с Intel 80386.
- **Причина:** Не устраивала лицензия MINIX (только для обучения) и плохая работа эмулятора терминала и ФС.
- **25 августа 1991:** Анонс в новостной группе MINIX:
  > «Hello everybody out there using minix — I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu) for 386(486) AT clones...»
- **17 сентября 1991:** Выложен исходный код (версия 0.01) для общедоступной загрузки.

### Операционные системы на основе Linux

- **Linux — это только ядро.** Официальный сайт: https://www.kernel.org
- **Дистрибутив:** Ядро + компоненты пользовательского режима (библиотеки, утилиты, средства разработки).
- **GNU/Linux:** Чаще всего используются компоненты GNU → корректное название.
- **Более 100 дистрибутивов:** Debian, Ubuntu, Mint, Gentoo, Raspberry Pi OS, Astra Linux, ROSA Linux, ALT Linux, RED OS.
- **Альтернативы:** Alpine Linux, OpenWRT (на основе musl libc / BusyBox / LLVM/Clang).
- **Лидерство:** Серверные и встраиваемые системы, мобильные устройства (Android).
- **Популярные дистрибутивы для ПК:** Ubuntu (>25%), Linux Mint, Arch Linux, Debian, Fedora.

## 4. 🖥️ Модель компьютера

### Основные компоненты

- **Процессор, память, периферийные устройства**, соединённые через **системную шину**.
- Процессор может произвольно обращаться к памяти и регистрам устройств.
- Устройства могут самостоятельно обращаться к памяти в режиме **прямого доступа (DMA)**.

### Память

- **Модель:** Линейный массив ячеек, доступных для чтения и записи.
- **Адрес:** Индекс (номер) ячейки памяти.
- **Адресное пространство памяти:** Множество всех допустимых адресов.
- **Байт:** Минимально адресуемый объём данных.

### Системная шина

- Обеспечивает обмен данными между компонентами.
- Передаёт **данные** и **адреса** этих данных.
- **Адресное пространство шины** — диапазон адресов, который может использовать шина.
- **Требование:** Адресное пространство шины ≥ адресного пространства памяти.

### Периферийные устройства

- Содержат **регистры**, доступные через шину как ячейки памяти.
- Адреса регистров должны находиться **вне** адресного пространства памяти **или** исключаться из него.
- **Чтение регистров** — определение состояния устройства и чтение данных.
- **Запись регистров** — управление устройством и запись данных.
- **DMA:** Устройства могут сами читать/писать в память.
- **Режим scatter/gather:** Передача блоков данных с автоинкрементом адресов, данные могут быть фрагментированы.
- **Прерывания:** Устройства могут генерировать прерывания.

### Процессор

- **Компоненты:** АЛУ, кэш, регистры общего назначения (РОН), счётчик команд (PC/IP), указатель стека (SP), регистр флагов.
- **Счётчик команд:** Адрес следующей инструкции.
- **Указатель стека:** Адрес вершины стека.
- **Регистр флагов:** Статус последней команды (переполнение, нулевой результат, чётность и т.п.).

### Выполнение программы

1. Процессор считывает код операции по адресу из PC и передаёт в АЛУ.
2. Определяет операнды и считывает их из памяти.
3. Инкрементирует PC (предполагая, что следующая команда — сразу за операндами).
4. Выполняет операцию.

**Условные переходы:**
- Модификация PC зависит от условия.
- Условие — логическое/арифметическое выражение (нулевое или ненулевое).
- **ZF (Zero Flag):** Устанавливается при нулевом результате.
- **JE < address >** — переход, если ZF = 1.
- **JNE < address >** — переход, если ZF = 0.
- Другие: JP/JNP (чётность), JS/JNS (знак), JO/JNO (переполнение).

## 5. 📚 Стек

- **Принцип:** LIFO (Last Input — First Output).
- **История:**
  - 1946 — Алан Тьюринг предложил идею стека для хранения адресов возврата.
  - 1957 — Клаус Самельсон и Фридрих Бауэр разработали современную концепцию (push-pop стек).
- **Использование:** Адреса возврата из подпрограмм и прерываний, передача аргументов, промежуточные результаты, временные переменные.

### Аппаратная реализация

- **Регистр SP** + команды **PUSH/POP**.
- **Инициализация:** Выделяется непрерывный участок памяти, в SP заносится первый адрес за областью стека.
- **PUSH < reg>:**
  1. Декрементирует SP.
  2. Записывает данные из < reg> в память по адресу из SP.
- **POP < reg>:**
  1. Считывает данные из памяти по адресу из SP в < reg>.
  2. Инкрементирует SP.
- **Защитные сегменты (guard):** Защищают стек от переполнения.

## 6. 🔄 Вызываемые подпрограммы

- **Цель:** Исключить дублирование кода в памяти.
- **Вызов:** Изменение значения PC.
- **Отличие от безусловного перехода:** Предусмотрен возврат в вызывающую программу.
- **Инструкции:**
  - **CALL < address>:**
    1. Помещает PC в стек.
    2. Записывает < address> в PC.
  - **RET:**
    1. Считывает адрес возврата с вершины стека в PC.

### Ограничения модели CALL/RET

- Перед RET в SP должно быть то же значение, что и при входе в подпрограмму.
- Количество POP ≤ количеству PUSH на любом этапе.
- Перед RET количество PUSH и POP должно совпадать.

## 7. ⚡ Прерывания

- **Прерывание** — автоматический вызов подпрограммы при наступлении события.
- **Обработчик прерывания** — заранее сопоставлен каждому событию.
- **Проблема:** Прерывание может повлиять на условный переход, если произойдёт между вычислением и проверкой условия.
- **Решение:** Регистр флагов сохраняется в стеке перед вызовом обработчика и восстанавливается после возврата.
- **Возврат:** Требуется специальная команда **IRET**.
- **Командные прерывания:** **INT < number>** — активация прерывания с номером.
- **Основа системных вызовов.**

## 8. 📐 Формальная модель выполнения программы

**Обозначения:**
- **P = {P_k}** — множество инструкций программы в памяти.
- **k** — адрес инструкции в памяти.
- **x_i** — состояние программы на i-ом шаге: x_i = v_1,i, ..., v_n,i, r_1,i, ..., r_m,i (значения переменных и регистров).

**Формула:**
$$[x_{i+1}, k_{i+1}] = P_{k_i}(x_i)$$

- **Начальное состояние x_1** хранится в исполняемом файле.
- **Точка входа (entry point)** — адрес первой инструкции k_1.

**Свойство:** Выполнение программы — процесс **без последействия**.
- Неважно, как программа пришла в состояние [x, k].
- Можно сохранить состояние, переключиться на другую программу и вернуться.
- **Состояние программы хранится в контексте процесса.**

## 9. 🧩 Определения процесса

> [!abstract] Процесс — это выполняющаяся программа.

**Различные определения:**

- **Microsoft:** Программа или команда, выполняемая на компьютере.
- **IBM:** Идентифицируемая абстракция совокупности взаимосвязанных системных ресурсов на основе отдельного и независимого виртуального адресного пространства.
- **Таненбаум:** Абстракция, описывающая выполняющуюся программу.
- **ГОСТ 19781-90:** Система действий, реализующая определённую функцию в системе обработки информации.

## 10. ⚙️ Реализация процесса

- **Процесс** — объект ОС, представленный в ядре структурой данных.
- **PCB (Process Control Block)** — блок управления процессом.
- **Ресурсы:** Дескрипторы открытых файлов, области памяти.
- **ВАП (Виртуальное Адресное Пространство):** Собственный диапазон адресов, изолированный от других процессов.
- **MMU (Memory Management Unit):** Аппаратный блок в процессоре для реализации ВАП.

## 11. 🧵 Легковесные процессы и потоки

### Легковесный процесс (LWP)

- ❌ **Не имеет** собственного ВАП.
- ✅ Несколько LWP разделяют одно ВАП.
- **Удобно:** Для совместной обработки данных, параллельных вычислений.
- **Планировщик** не делает различия между полновесными и легковесными процессами.

### Поток (thread)

- **Минимальная единица загрузки процессора.**
- Ассоциируется с выполнением одной функции (процедуры).
- В рамках одного процесса может исполняться много потоков одновременно.
- В *NIX-системах потоки обычно представлены LWP.
- **Главный поток:** Создаётся автоматически при создании процесса.
- **Дополнительные потоки:** Процесс может создавать LWP и делить с ними ВАП.

### Пользовательские потоки

- **Высоконагруженные системы:** Эффективное выполнение сотен тысяч подпрограмм с минимальными накладными расходами.
- **MS Windows:** Называются **волокнами (fiber)**.
- **C++20:** Называются **сопрограммами (coroutines)**.

### Сравнительная таблица

| Тип | Собственное ВАП | Единица планирования (ядром) |
| :--- | :---: | :---: |
| **Полновесный процесс** | ✅ Да | ✅ Да |
| **Легковесный процесс (LWP), поток (thread)** | ❌ Нет | ✅ Да |
| **Пользовательский поток, волокно (fiber), сопрограмма (coroutine)** | ❌ Нет | ❌ Нет |

## 12. 📁 Файл и файловая система

- **Файл** — именованный блок данных.
- **История термина:**
  - Февраль 1950 — RCA, рекламная заметка о запоминающем устройстве на электронно-лучевой трубке (Popular Science Magazine).
  - Ранее «файл» — стопка перфокарт.
- **Файловая система** — составная часть ОС, обеспечивающая поддержку файлов.
- **Первая ФС:** 1961, ОС **CTSS** (Compatible Time-Sharing System), MIT, для IBM-709.
