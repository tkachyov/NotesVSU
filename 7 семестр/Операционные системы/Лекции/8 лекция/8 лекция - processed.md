# ⚡ Лекция 8: Механизмы прерываний и их реализация в ОС

> [!info] Основная информация
> **Дата занятия:** 23.10.2026
> **Тема:** Разделение прерываний, контроллеры (LAPIC, NVIC), MSI, маскирование, приоритеты, многоуровневая обработка и модели в FreeBSD, NetBSD, Linux, Windows.

---

## 1. 🔌 Разделение канала запроса прерывания

> [!warning] Проблема
> Каналов запроса прерывания (физических пинов) часто не хватает для всех внешних устройств.

**Решение:** Несколько устройств подключаются к общему каналу (**разделение прерывания**).
- При обнаружении запроса процессор должен **опросить** все устройства на линии, чтобы выяснить, кто именно инициировал прерывание.

### Типы запросов прерываний (по уровню сигнала)

| Тип | Описание | Применение |
| :--- | :--- | :--- |
| **Edge-sensitive** (по фронту) | Запрос происходит **один раз** при изменении уровня сигнала (0→1 или 1→0). | Обычные прерывания |
| **Level-sensitive** (по уровню) | Прерывание **повторяется непрерывно**, пока уровень сигнала активен. | Удобно при разделении канала (устройство удерживает сигнал, пока его не обслужат) |

### Недостатки традиционной модели

1. **Аппаратные сложности:** Для каждого канала нужна отдельная цепь (пин) → усложняются платы и разъемы.
2. **Задержки (лаги):** Передается только факт прерывания, но не информация о событии. Процессору нужно опрашивать устройства, что замедляет обработку.

## 2. 📨 Прерывания, инициируемые сообщениями (MSI)

> [!abstract] Определение
> **MSI (Message Signaled Interrupts)** — прерывания, запрашиваемые устройствами посредством **прямой записи** данных в регистры контроллера прерываний процессора.

- Регистры контроллера отображаются на **адресное пространство памяти**.
- Устройства используют **DMA (Direct Memory Access)** для записи в эти регистры.
- **Преимущества:** Нет привязки к физическим пинам, передается информация о событии, нет необходимости в опросе.

---

## 3. 🎛️ Маскирование прерываний

- Обработку некоторых прерываний можно **запретить**, установив бит в специальном регистре процессора.
- Прерывания фиксируются логикой, но не обрабатываются, пока маска не будет снята.

> [!tip] Принцип работы
> Если маска = 1, сигнал запроса прерывания не проходит на логику запуска обработки (своеобразный логический вентиль И).

---

## 4. 🔄 Повторные прерывания и реентерабельность

> [!warning] Проблема
> Обработка прерывания занимает время → возможен новый запрос до завершения текущего.
> При новом запросе функция обработки **прерывается и перезапускается** (повторное вхождение).

- **Реентерабельность:** Обработчики прерываний обычно **не реентерабельны** из-за использования глобальных ресурсов (регистры устройства, статические переменные).
- **Решение:** На время обработки необходимо **маскировать прерывания** по текущему каналу.

## 5. 🏔️ Приоритеты прерываний

- Процессор фиксирует запросы в произвольные моменты, но переходит к обработке только после завершения текущей инструкции.
- Может накопиться несколько запросов → нужна **очередь** и **приоритеты**.
- Нельзя просто модифицировать PC при каждом запросе (потеряются прерывания).

### Модель вложенных (nested) прерываний

1. Прерывание с более высоким приоритетом **прерывает** обработку текущего.
2. Прерывание с более низким приоритетом **откладывается** до завершения текущего.

## 6. 🔀 Многоуровневая обработка прерываний

> [!abstract] Идея
> Разделить обработчик на две части: **первичный** (быстрый) и **вторичный** (долгий).

| Часть | Запуск | Блокировка прерываний | Задачи |
| :--- | :--- | :--- | :--- |
| **Первичный (Top Half)** | Аппаратурой через вектор | **Да** (блокирует часть прерываний) | Быстрая реакция, подтверждение, маскирование |
| **Вторичный (Bottom Half)** | Планируется первичным, выполняется ядром | **Нет** (не блокирует аппаратные) | Долгая обработка, работа с данными |

**Примеры вторичных обработчиков:**
- Высокоприоритетные процессы.
- Низкоприоритетные программные прерывания.
- Специальные объекты ядра: **DPC** в Windows, **bottom half** и **tasklet** в Linux.

### Цепочка обработчиков (Chaining)

- Адрес нового обработчика заносится в таблицу, старый сохраняется.
- Новый обработчик явно вызывает старый → формируется цепочка.
- **Плюсы:** Простота реализации.
- **Минусы:** Дублирование кода, каждый обработчик сохраняет/восстанавливает контекст, ОС не гарантирует вызов всех обработчиков.

### Параллельная модель (Базовый обработчик ОС)

- Обработчики — обычные функции, регистрируемые в ОС.
- Базовый системный обработчик в цикле вызывает все зарегистрированные функции.
- Цикл прерывается, если функция вернула статус «Обработано».

### Шторм прерываний

> [!danger] Опасность
> Если устройству не назначен обработчик, оно может генерировать бесконечные прерывания.
> **Решение:** Ядро обнаруживает шторм (если ни один обработчик не вернул «Обработано») и **блокирует проблемный канал**, из-за чего все устройства на этом канале перестают работать.

## 7. 🐧 Реализация в различных ОС

### FreeBSD

- Статическая переменная `event_list` — список обработчиков.
- Структура `struct intr_event` — связана с конкретным каналом.
- Список `intr_handler`, упорядоченный по приоритетам.
- Общесистемный обработчик последовательно запускает `ih_filter()` (аппаратный контекст) и `ih_handler()` (специальный поток ядра).

### NetBSD / OpenBSD

- Структура `cpu_info` для каждого процессора.
- Таблица указателей на источники прерываний (`intr_source`).
- Список `intrhand`, где `ih_fun()` — первичный обработчик.
- **Приоритеты (IPL):**
  - `IPL_HIGH` — можно использовать spin-блокировки.
  - `IPL_SCHED` — можно использовать планировщик.
  - `IPL_VM` — можно вызывать `malloc()`.
  - `IPL_SOFT*` — используются для вторичных обработчиков.

### Linux (ядро v6.12)

- Используется дерево **Maple tree** (`maple_tree sparse_irqs`).
- **`struct irq_desc`** — описание прерывания (ищется по номеру).
- **`struct irqaction`** — список обработчиков, разделяющих канал.
- **`handler()`** — первичный обработчик (возвращает `IRQ_NONE` или `IRQ_HANDLED`).
- **`thread_fn()`** — вторичный обработчик в контексте потока ядра (возвращает `IRQ_WAKE_THREAD` для его запуска).

## 8. 🪟 Обработка прерываний в Windows

- **IDT (Interrupt Descriptor Table)** — таблица прерываний процессора.
- **`struct KINTERRUPT`** — описание обработчика.
- **`ServiceRoutine()`** — функция обработки.
- Поле `DispatchCode` содержит бинарный код низкоуровневого общесистемного обработчика.

### Приоритеты (IRQL — Interrupt Request Level)

| IRQL | Примечание |
| :--- | :--- |
| `HIGH_LEVEL` | Остановка системы при крахе |
| `POWER_LEVEL` | Не используется |
| `IPI_LEVEL` | Многопроцессорные платформы |
| `CLOCK_LEVEL` | Главный таймер (планировщик) |
| `PROFILER_LEVEL` | Таймер профайлера |
| `CMCI_LEVEL` | Correctable Machine Check Interrupt (отказы HW) |
| `DISPATCH_LEVEL` | **Вторичные обработчики прерываний (DPC)** |
| `APC_LEVEL` | **APC (асинхронные вызовы процедур)** |
| `PASSIVE_LEVEL` | Обычный пользовательский режим |

### APC (Asynchronous Procedure Call)

- **Объект ядра** (`struct KAPC`), содержащий указатель на функцию и аргумент.
- Позволяет вызвать функцию в контексте **конкретного потока**.
- Назначение: копирование данных при вводе-выводе.
- Каждый поток имеет свою очередь APC. Проверяется при выборе потока на выполнение.

### DPC (Deferred Procedure Call)

- **Объект ядра** (`struct KDPC`), содержащий указатель на функцию и аргументы.
- Позволяет реализовать **отложенный вызов** функции на указанном процессоре.
- Назначение: поддержка **вторичных обработчиков прерываний**.
- Каждый процессор имеет свою очередь DPC.
- Проверяется при снижении IRQL. Функции выполняются до снижения IRQL ниже `DISPATCH_LEVEL`.

### Приоритеты DPC

| Приоритет | Позиция вставки | Переход к обработке |
| :--- | :--- | :--- |
| **High Importance** | В начало очереди | Немедленный |
| **Medium High Importance** | В конец очереди | Немедленный |
| **Low Importance** | В конец очереди | Отложенный |

### Потоковые (Threaded) DPC

- Выполняются в **системном потоке реального времени** на уровне `PASSIVE_LEVEL`.
- Могут вытесняться обычными DPC, но не другими потоковыми DPC.
- Появились в **Windows Vista**.
- Позволяют реализовать **третий уровень** обработки прерываний для снижения латентности в высоконагруженных системах.
