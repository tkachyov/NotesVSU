## 1. 🌊 Интерфейсы Wayland (продолжение)

> [!abstract] Определение
> **Интерфейс Wayland** — программный модуль, который:
> 1. Предоставляет функции для отправки клиентских запросов серверу (requests).
> 2. Поддерживает получение и обработку сообщений сервера о событиях (events).

- Для обработки событий клиент регистрирует **функции обратного вызова (callbacks)**, которые интерфейс автоматически вызывает при получении сообщения.
- Набор параметров функций определяется **протоколом Wayland** (описывается в XML).

### Типичная последовательность действий клиента Wayland

| Шаг | Действие | Код / Пояснение |
| :---: | :--- | :--- |
| **1** | Подключение к серверу | `wl_display = wl_display_connect(NULL)` |
| **2** | Получение реестра глобальных объектов | `wl_registry = wl_display_get_registry(wl_display)` |
| **3** | Получение требуемых объектов из реестра | `wl_display_roundtrip(wl_display)`<br>Например: компоновщик (`wl_compositor`), базовые операции оконного менеджера (`xdg_wm_base`) |
| **4** | Создание поверхности окна | `wl_surface = wl_compositor_create_surface(wl_compositor)`<br>*Поверхность — прямоугольная область, отображаемая на экране и принимающая ввод* |
| **5** | Назначение роли (toplevel) и получение интерфейса оконных операций | `xdg_surface = xdg_wm_base_get_xdg_surface(xdg_wm_base, wl_surface)`<br>`xdg_toplevel = xdg_surface_get_toplevel(xdg_surface)` |
| **6** | Создание буфера окна в разделяемой памяти и связывание с поверхностью | — |
| **7** | Ожидание сообщения от сервера | `wl_display_dispatch(display)` |

> [!tip] Пояснение
> Шаг 3 (`wl_display_roundtrip`) необходим для синхронизации с сервером — клиент отправляет запрос и ждёт ответа, чтобы получить список доступных глобальных объектов.
> `xdg_wm_base` — современный стандарт управления окнами в Wayland (заменяет устаревшие `wl_shell`).

## 2. 🪟 Оконная система Windows

> [!abstract] Архитектура
> Оконная система Windows **встроена в ядро** и реализуется модулем `win32k.sys`.

- **`win32k.sys`** (режим ядра):
  - Реализует менеджер окон и функции отрисовки.
  - Взаимодействует с драйверами HIDs (Human Interface Devices).
- **Пользовательский уровень (API):**

| Библиотека | Функции |
| :--- | :--- |
| **`user32.dll`** | Управление окнами и работа с сообщениями |
| **`gdi32.dll`** | Рисование графических объектов и вывод текста |

### Сообщения оконной системы Windows

```c
MSG msg; // структура сообщения

while (1) { // цикл получения сообщений
    GetMessage(&msg, 0, 0, 0); // ожидание сообщения
    DispatchMessage(&msg);     // вызов обработчика сообщения
}
```

- `DispatchMessage` вызывает **оконную функцию**, которая заранее регистрируется в системе для данного класса окон.
- **Оконная функция (Window Procedure):**
  ```c
  LRESULT WindowProc(HWND hWnd, UINT Msg, WPARAM wParam, LPARAM lParam)
  ```
  - `HWND` — дескриптор окна.
  - `Msg` — идентификатор сообщения.
  - `wParam`, `lParam` — параметры сообщения.

> [!note] Пояснение
> `GetMessage` — блокирующий вызов: поток засыпает, пока не появится сообщение. `DispatchMessage` маршрутизирует сообщение в `WindowProc` того окна, которому оно предназначено.

## 3. ⚡ Прерывания

> [!abstract] Определение
> **Механизм прерываний** — один из базовых аппаратных механизмов, реализуемых любым процессором.
> При наступлении **заранее ожидаемого события** управление передаётся заранее подготовленной подпрограмме — **обработчику прерывания**.
> Событие ожидаемо, но момент его возникновения **априорно неизвестен**.

**Без поддержки прерываний невозможно реализовать:**
- Вытесняющую многозадачность
- Виртуальную память
- Системные вызовы
- Точки останова при отладке
- Эффективную работу с периферийными устройствами

### Виды прерываний

| Категория | Тип | Описание |
| :--- | :--- | :--- |
| **Внешние (асинхронные, аппаратные)** | — | Вызываются периферийными устройствами |
| **Внутренние (синхронные, программные)** | **Командные прерывания** | Явно вызываются инструкцией программы (например, `INT`) |
| | **Исключения (Exceptions)** | Связаны с ошибками: деление на ноль, обращение к недоступному адресу памяти и т.п. |

> [!warning] Важно
> Исключения (exceptions) — это тоже прерывания, но они **синхронны** с выполнением指令. Внешние прерывания **асинхронны** — они происходят в произвольные моменты времени.

## 4. 📋 Вектор прерывания

> [!abstract] Проблема
> Процессор поддерживает несколько прерываний → необходим механизм быстрого вызова нужного обработчика.

**Решение: Косвенная адресация**

- Адреса обработчиков (**векторы прерываний**) размещаются в специальном массиве — **таблице векторов прерываний**.
- Начальный адрес таблицы **априорно известен** (записан в специальный регистр процессора).
- **Индекс** для доступа к таблице — **номер прерывания**.

### Схема работы

1. Устройство посылает запрос прерывания (INT) на вход процессора.
2. Процессор определяет номер прерывания (индекс в таблице).
3. Из таблицы по индексу загружается **вектор прерывания** (адрес обработчика).
4. Вектор загружается в **счётчик команд (PC)**.
5. Управление передаётся обработчику прерывания.

> [!tip] Пояснение
> Таблица векторов прерываний (IVT) находится по фиксированному адресу в памяти. Процессор аппаратно «знает», где её искать, что обеспечивает максимальную скорость реакции на прерывание.

## 5. 🔌 Разделение канала запроса прерывания

> [!warning] Проблема
> Каналов запроса прерывания может не хватать для всех внешних устройств.

**Решение: Разделение прерывания (IRQ Sharing)**

- Несколько устройств подключаются к **общему каналу** запроса прерывания.
- При обнаружении запроса процессор должен **опросить устройства**, разделяющие общий канал, чтобы выяснить, какое именно устройство инициировало запрос.

**Схема:**
```
Устр.1 ──┐
Устр.2 ──┼── INT ──→ Процессор
Устр.N ──┘
```

> [!note] Пояснение
> При разделении IRQ линия запроса остаётся общей, но обработчик должен уметь определить конкретное устройство (обычно через опрос регистров состояния устройств).

## 6. 🎛️ Контроллер прерываний

В современные процессоры обычно встраивается специальное устройство — **контроллер прерываний**.

| Контроллер | Архитектура | Описание |
| :--- | :--- | :--- |
| **LAPIC** (Local Advanced Programmable Interrupt Controller) | x86 | Локальный контроллер прерываний |
| **NVIC** (Nested Vectored Interrupt Controller) | ARM Cortex-M | Вложенный векторный контроллер прерываний |

**Функции контроллера:**
- Может взаимодействовать с **внешним контроллером прерываний**, увеличивающим число каналов запроса (физических входов/pin).
- Позволяет **сбалансировать нагрузку** по обработке прерываний на процессоры в многопроцессорных системах.

> [!tip] Пояснение
> LAPIC в x86-системах отвечает за приём и распределение прерываний между ядрами процессора. NVIC в ARM Cortex-M обеспечивает вложенную обработку прерываний с приоритетами, что критично для встраиваемых систем реального времени.
