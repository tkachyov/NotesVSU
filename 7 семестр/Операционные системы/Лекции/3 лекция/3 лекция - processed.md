## 1. 📁 Файл и файловая система

> [!abstract] Определение
> **Файл** — это именованный блок данных.

- **История термина:**
  - **Февраль 1950** — RCA, рекламная заметка о запоминающем устройстве на электронно-лучевой трубке (Popular Science Magazine, p. 96).
  - Ранее «файл» — стопка перфокарт.
- **Файловая система** — составная часть ОС, обеспечивающая поддержку файлов.
- **Первая ФС:** 1961, ОС **CTSS** (Compatible Time-Sharing System), MIT, для IBM-709.

## 2. 🔑 Дескриптор файла

- Чтобы файл стал доступен для чтения, записи или дополнения, его необходимо **открыть**.
- Файловая система для каждого открытого файла создаёт в памяти структуру данных.
- Процесс может открыть много файлов и работать с любым из них в произвольном порядке.
- **Задача идентификации:** Нужен механизм, указывающий, к какому именно файлу относится действие.
- **Решение:** Дескрипторы файлов.

> [!important] Дескриптор файла
> При успешном открытии файла ядро возвращает процессу **число** — дескриптор файла, которое нужно указывать при любой операции с этим файлом.

**Пример на C:**

```c
int fd = open("my_file", O_WRONLY | O_CREAT | O_TRUNC, 0666);
write(fd, "Hello World!\n", 13);
close(fd);
```

- **Дескриптор файла** — это индекс в таблице (массиве) открытых файлов процесса.

## 3. 📥📤 Стандартные потоки ввода-вывода

В *NIX новый процесс создаётся с **тремя уже открытыми файлами**:

| Дескриптор | Имя | Назначение | По умолчанию |
| :---: | :--- | :--- | :--- |
| **0** | stdin | Стандартный ввод | Клавиатура |
| **1** | stdout | Стандартный вывод | Монитор |
| **2** | stderr | Вывод сообщений об ошибках | Монитор |

- **Перенаправление ввода-вывода (redirection):** Ассоциацию дескрипторов можно изменить.
- **Пример в Linux:** Вызов `dup2(int oldfd, int newfd)`.

## 4. 🔄 Расширенная абстракция файла

Модель файла применима не только к хранению данных:

- **Периферийные устройства:** Запись в файл = передача команды/данных в устройство; чтение = получение статуса/данных.
- **Сетевые карты и модемы:** Удобно представлять как файлы.
- **Батарея ноутбука:** Файл только для чтения (температура, уровень заряда).
- **Объекты межпроцессного взаимодействия:** Каналы, очереди сообщений, разделяемые области памяти.
- **Процессы:** Можно представлять как файлы (отладка через чтение/запись).

## 5. 🧠 Ядро операционной системы

> [!abstract] Определение
> **Ядро** — основной компонент ОС, обеспечивающий управление аппаратными ресурсами, распределение ресурсов между процессами и реализацию API.

### Функции ядра

- **Управление аппаратными ресурсами.**
- **Распределение ресурсов** между конкурирующими процессами.
- **Реализация API:**
  - Создание новых (дочерних) процессов.
  - Завершение процессов.
  - Выделение/освобождение памяти.
  - Синхронизация работы процессов.
  - Передача данных между процессами (разделяемая память, сеть).
  - Создание, удаление, чтение и запись файлов.

### Абстракции, предоставляемые ядром

Ядро изолирует процессы от деталей аппаратной платформы:

| Реальный ресурс | Абстракция |
| :--- | :--- |
| Множество нумерованных дисковых блоков | **Файлы** |
| Несвязанные области памяти в ОЗУ и на дисках | **Виртуальное адресное пространство** |
| Регистры и прерывания HDD/SSD | **Абстрактные блочные устройства** |
| Регистры/прерывания сетевых адаптеров, низкоуровневые заголовки | **Абстрактные сетевые интерфейсы** |

### Состав традиционного ядра

| Компонент | Функции |
| :--- | :--- |
| **Система управления процессами** | Создание, планирование, синхронизация |
| **Система управления памятью** | Выделение памяти, защита данных |
| **Файловая система** | Создание, удаление, запись, чтение |
| **Низкоуровневые компоненты** | Обработка прерываний и др. |

## 6. 🛡️ Пользовательский режим и режим ядра

> [!warning] Проблема защиты данных
> Защита данных в памяти — одна из приоритетных задач ОС. Решается средствами **виртуальной памяти**.
> - Виртуальная память управляется таблицами трансляции и специальными регистрами процессора.
> - Необходимо запретить программам модифицировать эти структуры.
> - Но ОС тоже программа и должна управлять виртуальной памятью.

### Решение: два режима выполнения

| Режим | Доступ | Последствия нарушения |
| :--- | :--- | :--- |
| **Пользовательский (user mode)** | Запрещён доступ к некоторым областям памяти и регистрам, запрещены некоторые инструкции | Специальное прерывание — **исключение (exception)**, обработка ядром, процесс аварийно завершается |
| **Режим ядра (kernel mode)** | Полный доступ к памяти и регистрам, разрешены все инструкции | — |

## 7. 🔄 Переключение в режим ядра: системные вызовы

> [!important] Системный вызов
> **Системный вызов** — программно-аппаратный механизм, реализуемый на основе командных прерываний.

- **Обработчик прерывания** находится в защищённой области памяти, пользователь не может его изменить.
- В API системные вызовы инкапсулируются **функциями-обёртками (wrapper functions):**
  - `read()`, `write()`, `fork()`, `exit()` и т.п.
- **Специальные прерывания:** `SYSCALL` на Intel x86-64, `SVCall` в ARM.

### Схема реализации системного вызова

1. **API:** Программа вызывает функцию-обёртку (`read`, `write`, `open`...).
2. **Подготовка:** Номер системного вызова → в стек или регистр; аргументы → в стек или регистры.
3. **Командное прерывание:** Переводит процессор в режим ядра.
4. **Диспетчер системных вызовов:** Обработчик прерывания в составе ядра.
5. **Таблица системных вызовов:** Связывает номер вызова с функцией ядра.
6. **Функция ядра:** Выполняет запрошенную операцию.

### Пример: таблица системных вызовов в Linux (x86-64, ядро v5.10)

```c
asmlinkage const sys_call_ptr_t sys_call_table[__NR_syscall_max+1] = {
    [0 ... __NR_syscall_max] = &__x64_sys_ni_syscall,
#include <asm/syscalls_64.h>
};
```

Файл `syscalls_64.h` генерируется автоматически во время сборки ядра скриптом `syscalltbl.sh` из данных архитектурно-зависимой таблицы `syscalls_64.tbl`:

```
<number> <abi> <name> <entry point>
```

## 8. 💻 Пример «Hello, World!» в Linux x86-64

### Таблица регистров для системных вызовов

| № СВ | Результат | ARG0 | ARG1 | ARG2 | ARG3 | ARG4 | ARG5 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| rax | rax | rdi | rsi | rdx | r10 | r8 | r9 |

### Код на ассемблере

```asm
.text
_start:
    ; Системный вызов write(fd, buf, len)
    mov $1, %rax        ; 1 — номер системного вызова write
    mov $1, %rdi        ; 1 — файловый дескриптор stdout
    mov $message, %rsi  ; message — адрес буфера данных
    mov $15, %rdx       ; 15 — объём данных в буфере
    syscall

    ; Системный вызов exit(code)
    mov $60, %rax       ; 60 — номер системного вызова exit
    mov $0, %rdi        ; 0 — код возврата
    syscall

message:
    .ascii "Hello, World!\r\n"
    .global _start
```

**Сборка и линковка:**

```bash
gcc -c syscall-x86-64.s
ld syscall-x86-64.o -o syscall-x86-64
```

**Трассировка:**

```bash
strace ./syscall-x86-64
execve("./syscall-x86-64", ["./syscall-x86-64"], 0x7ffe37a04d20 /* 28 vars */) = 0
write(1, "Hello, World!\r\n", 15) = 15
exit(0) = ?
+++ exited with 0 +++
```

## 9. 📞 Системные вызовы: примеры

### Управление процессами

| Вызов | Назначение |
| :--- | :--- |
| `fork` | Создание дочернего процесса как копии вызывающего |
| `execve` | Замена программы процесса |
| `exit` | Завершение процесса |
| `nice` | Изменение приоритета процесса |
| `futex` | Ожидание указанного события для синхронизации |
| `nanosleep` | Приостановка выполнения на заданное время |

### Работа с файлами

| Вызов | Назначение |
| :--- | :--- |
| `open` | Открыть файл |
| `read` | Прочитать данные |
| `write` | Записать данные |
| `close` | Закрыть файл |

### Другие методы взаимодействия с ядром

- **Чтение/запись файлов в специальных ФС** (например, `/proc` в UNIX-подобных системах).
- **Специальные сокеты** (например, `AF_NETLINK` в Linux).

> [!note] Важно
> Эти способы **зависят от системных вызовов**! Для использования специального файла нужно открыть его через `open` и использовать `read`/`write`.

## 10. 🗺️ Разделение адресного пространства между пользователем и ядром

- **Проблема:** Если процессы — объекты ядра, где размещать код и данные самого ядра?
- **Вариант 1:** Отдельное ВАП ядра → частые переключения ВАП → падение производительности.
- **Решение:** Разделение адресного пространства процесса на две части:

| Часть | Свойства |
| :--- | :--- |
| **Пользовательское пространство** | Имеет разное отображение в разных процессах |
| **Пространство ядра** | Одинаково для всех ВАП. Любые данные и подпрограммы доступны ядру в любое время **без переключения ВАП**, независимо от активного процесса |

## 11. ⚡ Принципы реализации многозадачности

> [!abstract] Определение
> **Многозадачность** — способность ОС обслуживать более одного процесса.

- Если один процессор, в любой момент выполняется программа только одного процесса.
- ОС чередует исполнение процессов → **иллюзия одновременного выполнения** → **многозадачность с разделением времени**.

### Два подхода

| Подход | Кто определяет время переключения | Кто определяет следующий процесс |
| :--- | :--- | :--- |
| **Корпоративная (не вытесняющая)** | Текущая пользовательская программа | Планировщик ОС |
| **Вытесняющая (истинная)** | Планировщик ОС | Планировщик ОС |

- **Корпоративная:** Функция планирования распределена между ОС и пользовательскими программами.
- **Вытесняющая:** Полностью контролируется планировщиком (по таймеру — Timer_ISR).

## 12. 📊 Принципы управления ресурсами

> [!abstract] Определение
> **Ресурс** — любой объект, который ОС может предоставлять процессам.

**Примеры:** процессор, память, пространство памяти, диски, дисковое пространство, структуры данных, разделяемые библиотеки, файлы, процессы.

### Классификация ресурсов

| Тип | Определение | Примеры |
| :--- | :--- | :--- |
| **Неделимый** | Может использоваться только одним объектом одновременно | Процессор, диск, канал доступа к памяти |
| **Делимый** | Может распределяться частями | Пространство памяти, дисковое пространство |

### Проблема управления ресурсом

- Возникает при **конкуренции** между потребителями.
- ОС определяет порядок обслуживания и/или долю ресурса для каждого.

### Доступ к ресурсу

| Тип доступа | Описание |
| :--- | :--- |
| **С переключением** | ОС может отобрать ресурс у потребителя |
| **Без переключения** | ОС не может отобрать ресурс, должна ждать освобождения (пример: процессор при корпоративной многозадачности) |

### Стратегия управления ресурсом

**Стратегия** — цель управления (что хотят добиться).

| Стратегия | Цель |
| :--- | :--- |
| **Равного среднего времени ожидания** | Все потребители ждут одинаковое время |
| **Максимальной пропускной способности** | Обслужить максимум потребителей в единицу времени |
| **Справедливая** | Все потребители получают равные доли ресурса |

### Дисциплина управления ресурсом

**Дисциплина** — конкретный алгоритм, реализующий стратегию.

| Термин | Определение |
| :--- | :--- |
| **Оптимальная дисциплина** | Точно реализует стратегию |
| **Нереализуемая стратегия** | Для стратегии не существует оптимальной дисциплины |
| **Справедливая дисциплина** | Гарантирует каждому потребителю конечное время ожидания |
| **Предсказуемая дисциплина** | Позволяет точно оценить предстоящее время ожидания |

> [!warning] Важно
> - Оптимальная дисциплина может не существовать.
> - Даже если существует, не обязательно лучшая для практики.
> - **Справедливость** — обязательное требование для реальной ОС.
> - Для гарантированной справедливости: **учёт старения** или **ограничение числа откладываний**.
