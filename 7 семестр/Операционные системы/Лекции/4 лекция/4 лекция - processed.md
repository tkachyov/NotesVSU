## 1. 📊 Принципы управления ресурсами

> [!abstract] Определение
> **Ресурс** — любой объект, который ОС может предоставлять процессам.

**Примеры ресурсов:** процессор, память (устройство), пространство памяти, диски, дисковое пространство, структуры данных, разделяемые библиотеки, файлы, процессы.

### Классификация ресурсов

| Тип | Определение | Примеры |
| :--- | :--- | :--- |
| **Неделимый** | Может использоваться только одним объектом одновременно | Процессор, диск, канал доступа к памяти |
| **Делимый** | Может распределяться потребителями частями | Пространство памяти, дисковое пространство |

### Стратегии управления ресурсами

| Стратегия | Цель |
| :--- | :--- |
| **Равного среднего времени ожидания** | Все потребители ждут доступ одинаковое время |
| **Максимальной пропускной способности** | Обслужить максимум потребителей в единицу времени |
| **Справедливая** | Все потребители получают равные доли ресурса |

> [!note] Определение
> **Дисциплина управления ресурсом** — конкретный алгоритм, реализующий стратегию с некоторой степенью приближения.

### Свойства дисциплин

| Термин | Определение |
| :--- | :--- |
| **Оптимальная дисциплина** | Точно реализует стратегию |
| **Нереализуемая стратегия** | Для стратегии не существует оптимальной дисциплины |
| **Справедливая дисциплина** | Гарантирует каждому потребителю конечное время ожидания |
| **Предсказуемая дисциплина** | Позволяет точно оценить предстоящее время ожидания |

> [!warning] Важно
> - Оптимальная дисциплина может **не существовать**.
> - Даже если существует — не обязательно лучшая для практики.
> - **Справедливость** — обязательное требование для реальной ОС.
> - Для гарантированной справедливости: **учёт старения** или **ограничение числа откладываний**.

## 2. 🖥️ Операционная система как виртуальная машина

- Одни и те же программы могут выполняться на разных машинах (разные видеоадаптеры, диски, ОЗУ, процессоры).
- **На уровне исходных кодов** — нет зависимости от аппаратной платформы, только от интерфейсов ОС.
- **На уровне бинарного кода** — сохраняется зависимость от типа процессора, но нет зависимости от конфигурации машины.
- Программы пишутся **не для компьютера, а для операционной системы** (для Linux, для Windows и т.п.).

### Свойства виртуальной машины

- Пользовательские программы **изолированы** от аппаратной платформы и других программ.
- Нет доступа к устройствам и физической памяти.
- Все сервисы — через интерфейсы ОС и виртуальную память.
- Программы **не учитывают** существование других программ.
- ОС реализует виртуальную машину с изолированной средой и абстрактными ресурсами.

## 3. 🏛️ Архитектура операционной системы

> [!abstract] Определение
> **Архитектура** определяет состав и взаимодействие между компонентами ОС, влияет на достижимые показатели качества.

**Классификация по типу ядра:**
- Монолитное ядро
- Модульное ядро
- Микроядро
- Экзоядро

### Показатели качества ОС

| Показатель | Определение |
| :--- | :--- |
| **Надёжность** | Способность долго работать без перезагрузки |
| **Уязвимость** | Наличие возможностей для нарушения целостности |
| **Производительность** | Скорость выполнения программ |
| **Расширяемость** | Простота добавления новых возможностей |
| **Переносимость** | Простота переноса на другую платформу |

## 4. 🧱 Монолитное ядро

> [!abstract] Определение
> **Монолитное ядро** — набор процедур и данных, расположенных в общем адресном пространстве.

**Свойства:**
- Процедуры ядра могут обращаться к любым данным ядра, регистрам периферийных устройств и вызывать любые другие процедуры ядра.
- Ядро написано как **одна большая программа**.
- Всё работает в **ВАП ядра**.

### Показатели качества

| Показатель | Оценка |
| :--- | :---: |
| Надёжность | ✅ Высокая |
| Уязвимость | ✅ Низкая |
| Производительность | ✅ Высокая |
| Расширяемость | ❌ Плохая |
| Переносимость | ❌ Плохая |

> [!tip] Улучшение
> Расширяемость и переносимость можно улучшить за счёт **структурирования исходного кода** — выделения иерархических уровней и наложения ограничений на взаимодействие.

## 5. 🧩 Модульное ядро

> [!abstract] Определение
> **Модульное ядро** состоит из базового модуля и набора подключаемых модулей, расположенных в общем адресном пространстве.

| Компонент | Функции |
| :--- | :--- |
| **Базовый модуль** | Обработка прерываний и системных вызовов, управление процессами и памятью, поддержка базовых ФС и сетевых протоколов |
| **Подключаемые модули** | Драйверы устройств, дополнительные ФС, дополнительные сетевые протоколы |

### Распространение

- Широко используется в **Linux** и **Windows** для настольных ПК и ноутбуков.
- Благодаря удобству, хорошему сочетанию производительности, расширяемости и переносимости.

> [!warning] Проблемы
> Надёжность и уязвимость решают **организационными методами** — не устанавливать модули ядра из ненадёжных источников.

## 6. 🔬 Микроядро (µ-ядро)

> [!abstract] Основная идея
> **Микроядро** — вывести подключаемые модули в **пользовательский режим**.

**Цель:** Решение проблем надёжности и уязвимости.

**Свойства:**
- Изолированные от ядра и друг от друга сервисные модули не представляют угрозы.
- Сбой в одном модуле не нарушает работу ядра и других модулей.
- При сбое сервисный модуль может быть аварийно завершён ядром и перезапущен.
- Злоумышленник из сервисного модуля не может получить доступ к ядру или аппаратным средствам.
- **Сервисы** реализуются обычными процессами пользовательского режима.
- Каждый сервис исполняется в **собственном ВАП**.
- Возможности микроядра **предельно минимизированы**.

### Показатели качества

| Показатель | Оценка |
| :--- | :---: |
| Надёжность | ✅ Высокая |
| Уязвимость | ✅ Низкая |
| Производительность | ❌ Низкая |
| Расширяемость | ✅ Хорошая |
| Переносимость | ✅ Хорошая |

> [!warning] Причина низкой производительности
> Частые переключения между пользовательским режимом и режимом ядра, а также накладные расходы при обмене сообщениями между сервисами.

## 7. 🍏 Ядро Mach

> [!info] Историческая справка
> **Mach** — первое распространённое микроядро, оказавшее влияние на развитие всей микроядерной архитектуры.

- **Первоначальное название:** MUCK — Multi-User Communication Kernel (позже переименовано в Mach).
- **Разработка:** Университет Карнеги-Меллона (Carnegie Mellon University), 1985 год, для DEC VAX.
- **Цель:** Замена традиционному ядру BSD UNIX.
- **Развитие:** До 1994 года (Mach 3.0).

### Ключевые концепции

- **Порты** — основной механизм обмена данными между процессами (IPC).
  - Порт — разновидность **очереди сообщений**, реализованной за счёт разделяемой памяти.
  - Сервисы через системный вызов запрашивали доступ к порту, а затем использовали порт для быстрого взаимодействия с ядром.
- **Модель выполнения программ:**
  - **Задача (task)** — набор ресурсов, необходимых для выполнения потоков.
  - **Поток (thread)** — единица планирования, похожая на LWP, отвечает за выполнение программы в рамках задачи.
  - В одной задаче может быть **много потоков**, разделяющих общие ресурсы.
